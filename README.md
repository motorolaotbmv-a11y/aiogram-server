# АИОГРАМ — сервер

Backend АИОГРАМ на Node.js, Express и Supabase.

## Требования

- Node.js 18 или новее
- Supabase с таблицами `accounts`, `sessions`, `account_admins`, `admin_logs`
- Telegram-бот

## Переменные окружения

Добавь их в настройки хостинга (например, Render → Environment):

- `BOT_TOKEN` — токен Telegram-бота
- `SUPABASE_URL` — Project URL из Supabase
- `SUPABASE_SERVICE_ROLE_KEY` — секретный service role key. Только на сервере, никогда во фронтенде или публичном репозитории
- `CODE_SECRET` — длинная случайная секретная строка для HMAC-хеширования кодов и токенов
- `OWNER_TELEGRAM_ID` — числовой Telegram ID владельца. Без него владелец автоматически не назначается и админ-панель остаётся закрытой
- `PORT` — порт задаётся хостингом автоматически

Не публикуй значения этих переменных и не отправляй их в чаты.

## Запуск

```bash
npm install
npm start
```

## API

- `GET /health` — состояние сервера
- `POST /auth/verify` — вход по виртуальному номеру и одноразовому коду
- `GET /auth/me` — текущий аккаунт; нужен `Authorization: Bearer <token>`
- `POST /auth/logout` — завершение сессии
- `GET /admin/me` — проверка административной роли
- `GET /admin/overview` — число аккаунтов и активных сессий
- `GET /admin/accounts` — список аккаунтов
- `POST /admin/accounts/:id/disable` — отключение аккаунта (owner/admin)

## Защита

- Код входа действует 10 минут, хранится только как HMAC-хеш и используется один раз.
- После пяти неверных попыток вход по этому коду блокируется.
- Сессии хранятся в базе в виде HMAC-хешей, срок действия — 30 дней; выход отзывает сессию.
- Админ API проверяет роль на сервере. Роли: owner, admin, moderator.
- Первый владелец назначается только если Telegram ID отправителя совпадает с `OWNER_TELEGRAM_ID`.
- Действия администратора записываются в `admin_logs`.
- Админ API не предоставляет доступ к содержимому личных переписок.
- Таблицы серверной авторизации закрыты RLS для клиентского доступа; сервер использует service-role key только в переменных окружения.
- Ограничитель частоты входа хранится в памяти одного процесса; для нескольких экземпляров сервера нужен общий Redis-совместимый store.

Схема базы должна соответствовать текущему серверному коду. Не публикуй секретные переменные и не помещай service-role key во фронтенд.
