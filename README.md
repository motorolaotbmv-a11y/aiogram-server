# АИОГРАМ — сервер

Backend АИОГРАМ на Node.js, Express и Supabase. Регистрация и вход работают по email OTP; Telegram-бот не требуется.

## Требования

- Node.js 18 или новее
- Supabase Auth с включённым Email provider
- Таблицы `accounts`, `sessions`, `account_admins`, `admin_logs`

## Переменные окружения

Добавь их в настройки хостинга (например, Render → Environment):

- `SUPABASE_URL` — Project URL из Supabase
- `SUPABASE_ANON_KEY` — публичный anon key из Supabase (или `SUPABASE_PUBLISHABLE_KEY`, если проект использует новый формат ключей)
- `SUPABASE_SERVICE_ROLE_KEY` — секретный service role key. Только на сервере, никогда во фронтенде или публичном репозитории
- `CODE_SECRET` — длинная случайная секретная строка для HMAC-хеширования сессионных токенов
- `OWNER_EMAIL` — подтверждённый email владельца; только этот адрес автоматически получает роль owner
- `PORT` — порт задаётся хостингом автоматически

Не публикуй значения этих переменных и не отправляй их в чаты.

## Настройка email в Supabase

1. В Supabase открой **Authentication → Email Templates → Magic Link**.
2. В шаблоне письма размести код `{{ .Token }}`, например:

   ```html
   <h2>Код входа в АИОГРАМ</h2>
   <p>Твой одноразовый код: <strong>{{ .Token }}</strong></p>
   ```

3. Для отправки писем на обычные адреса настрой собственный SMTP в **Authentication → SMTP Settings**. Встроенная почта Supabase предназначена для тестов и отправляет письма только заранее разрешённым адресам команды проекта; для остальных адресов потребуется свой SMTP.

## Запуск

```bash
npm install
npm start
```

## Страницы и API

- `/` — регистрация и вход по email
- `/panel/` — административная панель
- `GET /health` — состояние сервера
- `POST /auth/email/request` — отправить одноразовый код на email
- `POST /auth/email/verify` — подтвердить код, создать аккаунт при первом входе и выдать сессию
- `GET /auth/me` — текущий аккаунт; нужен `Authorization: Bearer <token>`
- `POST /auth/logout` — завершение сессии
- `GET /admin/me` — проверка административной роли
- `GET /admin/overview` — число аккаунтов и активных сессий
- `GET /admin/accounts` — список аккаунтов
- `POST /admin/accounts/:id/disable` — отключение аккаунта (owner/admin)

## Защита

- Код email подтверждается через Supabase Auth и одноразовый OTP.
- Сервер ограничивает частоту запросов на отправку и проверку кодов.
- Виртуальный номер АИОГРАМ создаётся после успешного подтверждения email.
- Сессии хранятся в базе в виде HMAC-хешей, срок действия — 30 дней; выход отзывает сессию.
- Роль owner назначается только для адреса, совпадающего с `OWNER_EMAIL`, после подтверждения почты.
- Действия администратора записываются в `admin_logs`.
- Админ API не предоставляет доступ к содержимому личных переписок.
- Таблицы серверной авторизации закрыты RLS для клиентского доступа; service-role key используется только на сервере.
- Ограничитель частоты запросов хранится в памяти одного процесса; для нескольких экземпляров сервера нужен общий Redis-совместимый store.

Не публикуй секретные переменные и не помещай service-role key во фронтенд.
