# АИОГРАМ — сервер

Backend АИОГРАМ на Node.js, Express и Supabase.

## Требования

- Node.js 18 или новее
- Проект Supabase с таблицами `accounts` и `sessions`
- Telegram-бот и его токен

## Переменные окружения

Добавь их в настройках хостинга (например, Render → Environment):

- `BOT_TOKEN` — токен Telegram-бота
- `SUPABASE_URL` — Project URL из Supabase
- `SUPABASE_SERVICE_ROLE_KEY` — секретный service role key из Supabase. Храни только на сервере, никогда не помещай во фронтенд или публичный репозиторий
- `CODE_SECRET` — длинная случайная секретная строка для HMAC-хеширования кодов и токенов
- `PORT` — порт задаётся хостингом автоматически; вручную обычно не требуется

Не публикуй значения этих переменных и не отправляй их в чаты.

## Запуск

```bash
npm install
npm start
```

## API

- `GET /health` — проверка доступности сервера
- `POST /auth/verify` — вход по виртуальному номеру и одноразовому шестизначному коду. JSON: `{"number":"+7XXXXXXXX","code":"123456"}`
- `GET /auth/me` — данные текущего аккаунта; заголовок `Authorization: Bearer <token>`
- `POST /auth/logout` — завершение текущей сессии; тот же заголовок авторизации

Telegram-команды:

- `/start` — приветствие
- `/new` — создать аккаунт и получить данные для входа

## Важные замечания

- Коды входа и токены хранятся в базе только в виде HMAC-хешей.
- Для `/auth/verify` включено ограничение частоты запросов на IP.
- Сравнение хешей выполняется с использованием constant-time сравнения.
- Ограничитель частоты хранится в памяти одного процесса. Для нескольких экземпляров сервера нужен общий Redis-совместимый store.
- Схема Supabase должна соответствовать полям, которые использует `index.js`. Не запускай случайный SQL из интернета: сначала проверь существующие таблицы и ограничения.
